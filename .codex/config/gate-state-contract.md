# Gate State Contract

이 문서는 독립 게이트가 공통으로 사용하는 상태와 신호 반환 계약을 정의한다.

`UNCLASSIFIED`는 게이트 실행 상태다. `doc-impact`의 결과값인 `DOC_REQUIRED`, `DOC_NONE`, `DOC_UNDETERMINED`와 같은 도메인 판정값으로 사용하지 않는다.

## 상태

- `PASS`
  - 활성화된 게이트의 현재 scope와 완료 조건을 충족했다.
- `FAIL`
  - 실행한 검증이 실패했다.
  - 실패 원인을 수정한 뒤 같은 검증을 다시 실행해야 한다.
- `UNCLASSIFIED`
  - 입력이 없거나 요청·scope·diff와 충돌해 현재 게이트의 변경 성격 또는 다음 동작을 안전하게 확정할 수 없다.
  - 실행 불필요, 완료, 실패를 뜻하지 않는다.
  - 재분류 전에는 해당 게이트의 완료와 전체 작업 완료를 선언할 수 없다.

## `PASS` 효력과 재사용

`PASS`는 검증 당시의 게이트, 입력, scope와 직접 의존 대상이 유지되는 동안만 유효하다.

- 실패 원인 수정 뒤 입력과 직접 의존 대상이 달라지지 않은 선행 `PASS`는 재사용한다.
- 수정 diff가 입력 또는 직접 의존 대상을 바꾼 `PASS`만 효력을 무효화하고 다시 검증한다.
- 실패했던 검증은 항상 원인 수정 뒤 다시 실행한다.
- 공통 설정, 공유 계약, 검증 도구처럼 여러 게이트에 영향을 주는 변경은 직접 영향받는 `PASS`까지 무효화 범위를 넓힌다.
- 영향 범위를 안전하게 확정할 수 없으면 전체 재실행으로 바로 확대하지 않고 `UNCLASSIFIED`와 최소 확인 대상을 반환한다.
- 최소 확인 뒤에도 범위를 좁힐 수 없을 때만 영향 가능성이 있는 상위 검증 범위로 보수적으로 확대한다.

`PASS` 무효화는 새 공통 게이트 상태가 아니다. 기존 `PASS` 증거의 재사용 가능 여부를 나타내는 내부 수명주기이며, 실제 게이트 결과는 재검증 후 다시 `PASS`, `FAIL`, `UNCLASSIFIED` 중 하나로 확정한다.

## `FAIL` 반환 정보

skill과 script는 `FAIL`을 반환할 때 재시도 절차가 실패를 확인하기 위해 같은 검증을 먼저 반복하지 않도록 아래 정보를 함께 제공한다.

- 실패한 게이트와 검증
- 전달받은 입력과 scope
- 실행한 명령 또는 검증 식별자
- 실패 출력 요약과 원인 후보
- 수정 뒤 다시 실행할 동일 검증
- 실패 지점과 재개 지점
- 기존 runbook 축 후보 또는 축 미확정 신호
- 실패 전 유효한 선행 `PASS`와 각 검증의 입력·scope·직접 의존 대상

메인 에이전트는 이 정보를 받아 `verification-retry`와 `runbook` 게이트를 각각 판정한다. 최초 검증 실패만으로 skill이나 script가 다른 게이트를 직접 활성화하거나 runbook을 기록하지 않는다.

## `UNCLASSIFIED` 반환 정보

skill과 script는 `UNCLASSIFIED`를 반환할 때 아래 정보를 함께 제공한다.

- 분류하지 못한 대상
- 전달받은 기존 입력
- 입력이 부족하거나 충돌한다고 판단한 근거
- 가능한 후보 상태
- 분류에 필요한 최소 추가 확인 대상
- 중단된 절차의 재개 지점

## 재분류와 재개

1. 메인 에이전트는 반환된 근거와 최소 확인 대상만 확인한다.
2. 기존에 확정된 작업 수준과 다른 게이트를 처음부터 다시 판정하지 않는다.
3. 새 정보와 직접 관련된 상태 또는 게이트만 증분 판정한다.
4. 상태를 확정하면 중단된 동일 게이트의 재개 지점부터 계속한다.
5. 재분류 후에도 같은 불확실성이 남고 저장소 정보만으로 해소할 수 없으면 사용자에게 필요한 결정만 확인한다.

## 금지 사항

- `UNCLASSIFIED`를 `PASS`, 실행 불필요, 자동 생략으로 취급하지 않는다.
- 관련 없는 문서나 전체 저장소를 넓게 읽어 분류하지 않는다.
- 같은 근거로 의미 없이 재분류를 반복하지 않는다.
- skill이나 script가 메인을 대신해 의미론적 상태를 임의 확정하지 않는다.
- 실패 정보를 전달받은 뒤 원인 확인만을 위해 같은 검증을 다시 실행하지 않는다.
- 수정 영향을 받지 않은 선행 `PASS`를 관성적으로 다시 검증하지 않는다.
- 수정 영향을 받은 선행 `PASS`를 재사용하지 않는다.
- 불확실성을 해소하지 않은 채 다음 게이트나 최종 완료로 넘어가지 않는다.
