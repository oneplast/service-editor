# Runbook Trigger

이 skill은 실패·반복 실수·복구 신호가 확인됐을 때 관련 작업 축의 runbook 파일 하나로 분기하는 절차다.

## 사용할 때

- 문서 체계, followup, topic, `.codex` 작업에서 읽기 순서나 경로 판단이 흔들릴 때
- 구현 검증이나 테스트에서 실제 실패가 발생했거나 기존 실패 축의 예방 체크포인트가 직접 필요한 경우
- 검증 직전 현재 작업에 알려진 반복 실패가 있는지 확인해야 하는 경우
- 세션 재개 후 followup만으로 실패·복구 상태를 확정할 수 없는 경우
- 같은 문서 작업 실수가 두 번 이상 반복될 때
- 인덱스 문서에 절차형 내용을 넣으려 할 때
- 전역 규칙을 하위 문서나 skill에 다시 적으려 할 때

정상적인 문서 수정, 테스트 실행, 구현 검증을 시작한다는 이유만으로 사용하지 않는다.

## 절차

1. 확인된 실패나 이상 징후를 한 문장으로 고정한다.
2. `docs/runbook/README.md`에서 현재 증상과 연결된 축 하나를 고른다.
3. 선택한 runbook의 `검증/자기점검 때 볼 분기` 또는 가장 가까운 실패 사례만 먼저 확인한다.
4. 그 항목이 요구하는 원문 문서와 followup 상태만 다시 읽고 작업을 이어간다.
5. 같은 문제 축이 확인되면 기존 runbook 파일에 새 케이스를 추가하거나 기존 항목을 보강한다.
6. runbook 체계, 운영 규칙, 템플릿 또는 workflow 계약까지 바뀐 경우 `doc-governance` 필요 신호를 메인 에이전트에 반환한다.

## 하지 말 것

- runbook 디렉토리 전체를 넓게 읽지 않는다.
- 실패나 복구 신호 없이 예방을 이유로 runbook을 선행 로드하지 않는다.
- 증상을 정리하지 않은 채 감으로 여러 문서를 다시 열지 않는다.
- topic 문서에 복구 절차를 길게 적지 않는다.
- 반복 에러를 runbook 갱신 없이 끝내지 않는다.
- 일반 실패 사례 추가만으로 `doc-governance`나 prompts 게이트를 자동 활성화하지 않는다.
- 다른 독립 게이트를 직접 활성화하거나 관련 skill을 연쇄 실행하지 않는다.
