# Commit Msg

이 skill은 커밋 메시지 초안 작성 전용이다. 커밋 실행은 사용자가 별도로 명시적으로 요청한 경우에만 수행한다.
staging이 필요하면 먼저 `commit-stage`를 사용한다. 이 skill은 자체적으로 파일을 stage하지 않는다.

## 기본 원칙

- 세션 기억에 의존하지 않고 현재 로컬 변경을 기준으로 작성한다.
- staged 변경이 있으면 staged diff만 커밋 메시지 근거로 사용한다.
- staged 변경이 없으면 unstaged diff 기준 초안임을 명시한다.
- 커밋 실행 요청을 받았더라도 새로 `git add`하지 않고 현재 staged 상태만 커밋 대상으로 본다.
- `.gitignore` 대상 경로나 ignored 변경은 staged 여부와 관계없이 제목과 본문에 포함하지 않는다.
- ignored 대상 경로가 staged에 포함되어 있으면 메시지에는 넣지 말고 사용자에게 staged 상태 확인을 권고한다.
- 실제 수행하지 않은 변경, 검증, 기록은 쓰지 않는다.
- 변경 내용을 과장하지 않고 diff로 확인되는 사실만 적는다.
- 최근 커밋은 기본으로 읽지 않는다. 사용자가 최근 커밋 확인을 요청했거나 현재 스타일이 불명확할 때만 최소 범위로 확인한다.

## 확인 순서

1. `git status --short`로 변경 상태를 확인한다.
2. staged 변경이 있으면 `git diff --cached --stat`과 필요한 범위의 staged diff만 확인한다.
3. staged 변경이 없으면 unstaged 기준 초안임을 알리고, `git diff --stat` 뒤 필요한 범위의 diff만 확인한다.
4. diff만으로 의도를 알 수 없을 때만 관련 followup, worklog, 최근 커밋 형식을 최소 확인한다.

## 메시지 스타일

제목:

```text
<type>: <작업 요약>
```

- `type`은 실제 변경 성격에 맞게 고른다.
- `feat`: 새 기능이나 새 capability 추가
- `fix`: 버그 수정
- `refactor`: 동작 의도는 유지하면서 구조나 책임 경계 변경
- `docs`: 문서 자체의 기준, 설명, 기록 변경
- `test`: 테스트, 검증, fixture, 회귀 검증 추가 또는 변경
- `chore`: 운영성 작업, 의존성, 설정 정리 등 위 범주에 들어가지 않는 보조 변경

본문:

```text
1. <큰 변경 단위>했습니다.
  - <해당 변경 단위에 속한 사실>
  - <해당 변경 단위에 속한 사실>

2. <큰 변경 단위>했습니다.
  - <해당 변경 단위에 속한 사실>
  - <해당 변경 단위에 속한 사실>
```

- 번호 항목은 실제 변경의 큰 단위 기준으로만 나눈다.
- 각 번호 아래에는 해당 변경 단위에 속하는 사실만 bullet로 적는다.
- 특정 유형의 내용을 별도 항목으로 강제하지 않는다.
- 보통 각 번호 아래 bullet은 2~3개로 유지하되, 변경 규모에 맞게 조절한다.
- 문체는 기존 커밋처럼 `했습니다` 형태를 기본으로 한다.

## 출력 기준

- 사용자가 메시지만 요청하면 제목과 본문만 제시하고 커밋하지 않는다.
- 사용자가 커밋까지 요청하면 메시지를 제시한 뒤, 이미 명시 승인된 경우에만 커밋을 실행한다.
- ignored 대상 변경이 있으면 커밋 메시지에 포함하지 않았다고 짧게 알린다.
- 검증 실행 여부가 불명확하면 검증을 수행했다고 쓰지 않는다.
