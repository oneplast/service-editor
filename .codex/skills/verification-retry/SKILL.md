# Verification Retry

이 skill은 검증 실패가 나왔을 때 수정 후 재검증을 반복하고, 실패 축이 명확하면 관련 runbook에 바로 기록하는 절차다.

## 사용할 때

- 문서 거버넌스 검증이나 구현 검증에서 `FAIL`이 나온 작업
- 코드 변경 후 테스트 실패를 닫아야 하는 작업
- 같은 실패가 반복되어 runbook 케이스 승격이 필요한 작업

## 절차

1. 관련 검증 스크립트를 한 번 실행해 실패 종류를 확인한다.
2. 현재 작업 축의 runbook을 먼저 읽고 예방 체크포인트를 다시 본다.
3. 가능하면 `--scope-file`로 현재 작업 파일 목록을 고정한다.
4. followup 파일이 있다면 `현재 상태`의 `검증 단계`가 `검증 대기`인지 먼저 확인한다.
5. 실패 원인을 고친다.
6. 필요하면 `.codex/scripts/verify-and-retry.sh --scope-file <path> --followup-file <path> --label <task>`를 실행한다.
7. 스크립트는 현재 실패 유형이 명확하면 관련 runbook을 자동 선택하고 바로 케이스를 추가한다.
8. 실패 축이 애매하면 새 runbook 파일을 자동 생성하지 않고 후보 안을 정리해 사용자 확인을 받는다.

## 하지 말 것

- 같은 입력으로 수정 없이 검증만 반복하지 않는다.
- `FAIL`이 남아 있는데 완료로 간주하지 않는다.
- 실패 케이스 기록 없이 반복 실패를 그냥 넘기고 끝내지 않는다.
