# Verification Retry

이 skill은 검증 실패 정보를 이어받아 수정 후 동일 검증을 재개하고, 메인이 확정한 실패 축을 관련 runbook에 반영하는 절차다.

## 사용할 때

- 문서 거버넌스 검증이나 구현 검증에서 `FAIL`이 나온 작업
- 코드 변경 후 테스트 실패를 닫아야 하는 작업
- 같은 실패가 반복되어 runbook 케이스 승격이 필요한 작업

## 절차

1. 최초 검증이 반환한 실패 게이트, 입력·scope, 실행한 검증, 실패 요약, 재개 지점과 유효한 선행 `PASS` 정보를 전달받는다.
2. 실패 정보가 없거나 현재 scope와 충돌하면 같은 검증을 다시 실행하지 않고 `UNCLASSIFIED`와 최소 추가 확인 대상을 메인 에이전트에 반환한다.
3. 기존 실패 축의 예방 체크포인트가 필요하면 `runbook` 필요 신호와 축 후보를 메인 에이전트에 반환한다. 메인이 runbook 게이트와 축을 확정한 경우에만 관련 파일 하나를 읽는다.
4. 가능하면 전달받은 `--scope-file`로 현재 작업 파일 목록을 유지한다.
5. followup 파일이 있다면 `현재 상태`의 `검증 단계`가 `검증 대기`인지 확인한다.
6. 실패 원인을 고친다.
7. 수정 diff와 선행 `PASS`의 입력·scope·직접 의존 대상을 비교해 영향받은 `PASS` 후보를 계산한다.
8. 영향이 명확한 `PASS`만 무효화하고, 영향받지 않은 `PASS`는 재사용한다. 영향 범위가 불명확하면 `UNCLASSIFIED`와 최소 추가 확인 대상을 메인 에이전트에 반환한다.
9. 무효화된 선행 검증을 필요한 순서로 실행한 뒤 실패 지점의 동일 검증을 다시 실행한다.
10. 재검증이 `PASS`이면 중단된 게이트의 재개 지점으로 반환하고, 다시 `FAIL`이면 갱신된 실패 정보와 현재 유효한 `PASS` 정보를 반환한다.
11. 메인이 runbook 게이트와 실패 축을 확정한 경우에만 관련 기존 runbook에 케이스를 추가한다.
12. 실패 축이 애매하면 새 runbook 파일을 자동 생성하지 않고 `UNCLASSIFIED`와 후보 안을 메인 에이전트에 반환한다.

## 하지 말 것

- 같은 입력으로 수정 없이 검증만 반복하지 않는다.
- 전달받은 실패를 확인한다는 이유로 최초 검증을 다시 실행하지 않는다.
- 수정 영향을 받지 않은 선행 `PASS`를 다시 실행하지 않는다.
- 수정 영향을 받은 선행 `PASS`를 유효한 결과로 재사용하지 않는다.
- `FAIL`이 남아 있는데 완료로 간주하지 않는다.
- 실패 케이스 기록 없이 반복 실패를 그냥 넘기고 끝내지 않는다.
- runbook 게이트와 실패 축을 이 skill이나 script가 경로만으로 임의 확정하지 않는다.
- 재분류가 끝나면 실패가 발생한 동일 검증 절차부터 재개하고, 이미 통과한 게이트를 반복하지 않는다.
